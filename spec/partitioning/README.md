# Partition function

Every component that needs a channel's partition must compute exactly what Kafka's default partitioner computes ([ADR-0004](../../docs/adr/0004-fixed-partitions-and-partition-function.md), [ADR-0021](../../docs/adr/0021-partition-count-per-installation.md)).

```
key       = channel_id as 8-byte big-endian two's complement (Kafka's LongSerializer)
hash      = murmur2(key)                 -- Kafka's Utils.murmur2, seed 0x9747b28c, signed 32-bit result
partition = (hash & 0x7fffffff) % N      -- Utils.toPositive, N = partition count of this installation
```

- **N** is fixed per installation: Small 16, Medium 64, Large 512, local dev 8–16. Clients receive it in the `Welcome` frame.
- **Rust producers** use librdkafka with `partitioner = murmur2_random`, which matches Kafka's Java partitioner for non-null keys; services that compute partitions themselves use `crates/xmsg-partition`.

## Test vectors

[`vectors.csv`](vectors.csv) has one row per channel ID: the key bytes, the signed murmur2 hash and the partition for N = 8, 16, 64 and 512. It's generated by `tools/gen-partition-vectors.py` and **cross-checked against Kafka's own `Utils.murmur2`** in the sequencer's tests, so a mistake in the generator fails CI.

Implementations tested against it:

| Language | Code | Test |
|---|---|---|
| Kotlin | `services/sequencer/.../Partitioning.kt` (uses Kafka's `Utils`) | `PartitioningTest` |
| Rust | `crates/xmsg-partition` | `cargo test -p xmsg-partition` |
| Elixir | `services/gateway/lib/xmsg_gateway/partition.ex` | `mix test` |
| TypeScript | `clients/core/src/partition.ts` | `node --test` |
